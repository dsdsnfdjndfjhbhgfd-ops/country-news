# ev.news

Сайт: https://evnews.site/ (главная о проекте; старый адрес https://dsdsnfdjndfjhbhgfd-ops.github.io/country-news/ переадресует туда), лента: `news.html#RU`, страница события: `article.html?c=RU&u=<ссылка на статью>`

Вводишь страну и видишь главные события недели: только то, о чём пишут несколько изданий, без спорта и шоу-бизнеса.

- Новости берутся из открытой базы мировых СМИ [GDELT](https://www.gdeltproject.org/), русские и английские источники за 7 дней.
- 18 ключевых стран собираются заранее GitHub Actions каждые 15 минут (`scripts/prefetch.mjs` → `data/*.json`) и открываются сразу.
- Остальные страны запрашиваются у GDELT прямо из браузера (15–30 секунд), результат кэшируется в браузере на 30 минут.
- Ссылка на страну: `#KZ`, `#DE` и т. п.

## Аккаунты

Вход и регистрация через Supabase Auth (проект `ev-news`). Таблицы: `profiles` (мои страны, настройки ленты) и `saved` (сохранённые новости), доступ только к своим строкам (RLS). Код: `assets/account.js`, страница кабинета `account.html`. Лента (`news.html`) показывается только вошедшим пользователям.

**Рейтинг изданий** (`ratings.html`, `assets/ratings.js`). Список изданий лежит в таблице `outlets`. Оценки 1–5 хранятся в `outlet_ratings`: одна оценка на пользователя и издание, каждый видит и меняет только свои строки. Итоги для всех, без имён проголосовавших, отдаёт функция `outlet_stats()`. Место в рейтинге считается с поправкой на число оценок: к оценкам издания добавляются 3 условных голоса со средней оценкой по всем изданиям. Если в `scripts/prefetch.mjs` появляется новое издание, его нужно добавить и в `outlets`.

## Безопасность и производительность

- Все скрипты сайта лежат в `assets/`; на страницах стоит политика безопасности (CSP): браузер запускает только скрипты самого сайта.
- Библиотека входа (supabase-js) и карта суши для глобуса хранятся закреплёнными копиями в `assets/vendor/` (версии в `VERSIONS.txt`). Обновить их: задание «Обновить сторонние файлы» в Actions.
- В базе стоят ограничения на размер и формат данных и не больше 500 сохранённых новостей на человека.
- Новости хранятся в ветке `data`, которая перезаписывается целиком при каждом сборе (без истории), поэтому старые новости не копятся. Сайт публикуется заданием «Сайт и новости» через GitHub Actions: код из `main` плюс данные из `data`.
- Лента грузит облегчённые файлы `data/XX.json`; полные копии для сборщика лежат в `data/full/` (на сайт не публикуются). Файлы версионируются по `data/status.json`, поэтому повторные заходы берут их из кэша браузера.

## VIP-подписка

250 ₽ за 30 дней, оформляется в кабинете (`account.html`). Пока **тестовый режим**: деньги не списываются. Подписка открывает чат с ИИ по странам и 25 пересказов в сутки вместо 3. В шапке у подписчика рядом с «Кабинет» стоит метка VIP, в коде проверка — `Account.vip`.

- Таблицы `subscriptions` (одна строка на человека, `expires_at`) и `payments` (история). Читать можно только свои строки, записывает только Edge Function `subscribe` (код в `supabase/functions/subscribe/index.ts`).
- Без ключей ЮKassa функция сразу включает подписку. Повторная покупка продлевает её ещё на 30 дней.

**Как подключить ЮKassa:**
1. В Supabase → Edge Functions → Secrets добавить `YOOKASSA_SHOP_ID` (shopId) и `YOOKASSA_SECRET_KEY` (секретный ключ из личного кабинета ЮKassa). С этого момента кнопка ведёт на страницу оплаты ЮKassa, а после оплаты читатель возвращается в кабинет.
2. В личном кабинете ЮKassa → Интеграция → HTTP-уведомления указать `https://bsgidggxlzinntgdnxgt.supabase.co/functions/v1/subscribe` и событие `payment.succeeded` (и `payment.canceled`). Функция не верит уведомлению на слово: она перечитывает платёж через API ЮKassa.
3. Если магазин отправляет чеки через ЮKassa (54-ФЗ), добавить секрет `YOOKASSA_RECEIPT=1` и при необходимости `YOOKASSA_VAT_CODE` (по умолчанию 1 — без НДС).
4. Цена меняется секретом `VIP_PRICE_RUB`; текст «250 ₽» в кабинете — в `assets/cabinet.js`.

## Администраторы

Администраторы могут удалять любые комментарии. Список хранится в закрытой таблице `private.admins`, изменить его можно только SQL-запросом в панели Supabase:

```sql
-- назначить
insert into private.admins (user_id) select id from auth.users where email = 'почта@пример.ru';
-- снять
delete from private.admins where user_id = (select id from auth.users where email = 'почта@пример.ru');
```

## Краткое изложение событий («Кратко»)

- **По расписанию.** При каждой сборке `scripts/prefetch.mjs` просит ИИ написать 2–3 предложения для 25 лучших событий каждой страны (сначала самые верхние в ленте). Результат: `data/summary.json`. **Весь ИИ сайта работает через DeepSeek**: сейчас это сервис `https://plusvibeapi.ru/v1` с моделью `deepseek-v4.1-flash:cxb` (секрет `LLM_KEY_EXTRA1`, переменные `LLM_BASE_EXTRA1` и `LLM_MODEL_EXTRA1`). **Gemini и Groq отключены**: сервис с их адресом или с именем `GEMINI` / `GROQ` пропускается, даже если ключ остался в секретах (поэтому старый `LLM_API_KEY` с адресом Gemini тоже не используется).
- **Пул нейросетей.** Можно подключить несколько сервисов сразу (`scripts/ai-pool.mjs`): каждый ключ добавляется секретом `LLM_KEY_<ИМЯ>` (`LLM_KEY_MISTRAL`, `LLM_KEY_CEREBRAS`, `LLM_KEY_DEEPSEEK`, `LLM_KEY_OPENROUTER`, `LLM_KEY_TOGETHER`, `LLM_KEY_SAMBANOVA`, `LLM_KEY_NVIDIA`, `LLM_KEY_OPENAI`; любой другой сервис — секрет `LLM_KEY_EXTRA1` и переменная `LLM_BASE_EXTRA1` с адресом OpenAI-совместимого API). Необязательно: `LLM_MODEL_<ИМЯ>`, `LLM_BATCH_<ИМЯ>` (событий за запрос), `LLM_GAP_<ИМЯ>` (минут между запросами), `LLM_RUNS_<ИМЯ>` (запросов за один сбор), `LLM_PARALLEL_<ИМЯ>` (сколько из них идут одновременно), `LLM_MAX_TOKENS` (предел длины ответа, по умолчанию 30 000: хватает и «думающим» моделям). Изложение — 3–5 предложений с участниками, цифрами, контекстом и позициями сторон; более старые короткие изложения постепенно переписываются. Работает как цепочка: каждый свободный сервис берёт свою пачку событий, у кого кончился лимит (429) или случилась ошибка, тот отдыхает (время берётся из ответа сервиса), а пачку подхватывает следующий. Состояние каждого сервиса хранится в `data/summary.json` (поле `pool`), ключи туда не попадают.
- **Обзоры стран.** Для каждой страны ИИ пишет три сочинения по 200–300 слов — о главной проблеме в политике, безопасности и экономике — по событиям последних двух дней (с их изложениями). Обновляются раз в 6 часов (`ESSAY_HOURS`), лежат в `data/essays.json` и показываются в ленте над новостями.
- **По запросу читателя.** Если у события нет изложения, на странице события есть кнопка «Пересказать с помощью ИИ». Она вызывает Edge Function `summarize` в Supabase. Функция проверяет вход, лимиты (в сутки: 25 запросов с VIP-подпиской, 3 без неё, 400 всего на сайт), берёт заголовки только из опубликованных данных сайта и сохраняет изложение и «Почему это важно» (колонки `summary` и `why`) в `event_summaries` для всех. Старые изложения без «Почему это важно» по запросу пишутся заново. ИИ — DeepSeek. Ключ хранится в секретах Supabase (Edge Functions → Secrets): `DEEPSEEK_API_KEY` (тот же ключ plusvibeapi.ru, что и в GitHub-секрете `LLM_KEY_EXTRA1`); необязательно `DEEPSEEK_BASE_URL` (по умолчанию `https://plusvibeapi.ru/v1`) и `DEEPSEEK_MODEL` (по умолчанию `deepseek-v4.1-flash:cxb`). Старые секреты `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` (Gemini) функции больше не читают, их можно удалить. В браузер и в репозиторий ключ не попадает.

## Чат с ИИ по стране (только VIP)

Отдельная страница `chat.html` (код `assets/chat.js`), ссылка «Чат с ИИ» есть в меню всех страниц. Читатель выбирает одну из 18 стран и спрашивает о её новостях за последние два дня или о политике, безопасности и экономике в целом. ИИ получает 25 главных событий страны (сгруппированы и упорядочены так же, как в ленте, функцией `cluster` из `assets/core.js`) и ссылается на них номерами `[3]`, которые открывают страницу события. Список этих событий раскрывается под чатом. У VIP-читателя у каждого события в ленте есть ссылка «Спросить ИИ»: `chat.html?c=RU&u=<ссылка>` открывает чат с готовым вопросом об этом событии, событие идёт в списке первым. Без входа страница предлагает войти, без VIP показывает, что даёт подписка. Разговор хранится только в открытой вкладке (`sessionStorage`), отдельно для каждой страны.

- Edge Function `chat` (`supabase/functions/chat/index.ts`): проверяет вход и активную VIP-подписку, берёт заголовки, изложения и обзоры только из опубликованных данных сайта (браузер присылает лишь код страны, ссылки событий ленты и сам разговор: до 8 последних сообщений, вопрос до 1000 символов).
- **Лимит: 50 000 токенов в сутки на человека** — вопрос, история разговора, новости и ответ вместе. Сутки начинаются в 00:00 по Москве. Перед запросом к ИИ функция резервирует токены (`chat_reserve`, атомарно, поэтому два запроса одновременно не превысят лимит), после ответа записывает реальный расход из ответа сервиса (`chat_settle`). Остаток показывается под чатом.
- Таблица `chat_usage` (человек, день, токены, число запросов): читать можно только свои строки, пишет только функция. Общий предел на весь сайт — секрет `CHAT_GLOBAL_DAILY_TOKENS` (по умолчанию 3 000 000 токенов в сутки).
- ИИ тот же, что у пересказа: DeepSeek с ключом `DEEPSEEK_API_KEY` в секретах Supabase. **Модель поумнее только для чата:** секрет `CHAT_MODEL` — название модели того же сервиса (можно несколько через запятую). Если она не ответит, чат отвечает обычной моделью `DEEPSEEK_MODEL`. Ответ получает до 4000 токенов вместе с размышлениями модели (меняется секретом `CHAT_MAX_TOKENS`), уровень рассуждений можно задать секретом `CHAT_REASONING` (`low` / `medium` / `high`), если сервис его поддерживает. Размышления модели тоже входят в дневной лимит 50 000 токенов. Лимит и час сброса — константы `DAILY_TOKENS` и `RESET_HOUR_MSK` в начале функции (и тексты в `assets/account.js`, `assets/chat.js`, `chat.html`).
