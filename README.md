# ev.news

Сайт: https://dsdsnfdjndfjhbhgfd-ops.github.io/country-news/ (главная о проекте), лента: `news.html#RU`, страница события: `article.html?c=RU&u=<ссылка на статью>`

Вводишь страну и видишь главные события недели: только то, о чём пишут несколько изданий, без спорта и шоу-бизнеса.

- Новости берутся из открытой базы мировых СМИ [GDELT](https://www.gdeltproject.org/), русские и английские источники за 7 дней.
- 18 ключевых стран собираются заранее GitHub Actions каждые 15 минут (`scripts/prefetch.mjs` → `data/*.json`) и открываются сразу.
- Остальные страны запрашиваются у GDELT прямо из браузера (15–30 секунд), результат кэшируется в браузере на 30 минут.
- Ссылка на страну: `#KZ`, `#DE` и т. п.

## Аккаунты

Вход и регистрация через Supabase Auth (проект `ev-news`). Таблицы: `profiles` (мои страны, настройки ленты) и `saved` (сохранённые новости), доступ только к своим строкам (RLS). Код: `assets/account.js`, страница кабинета `account.html`. Лента (`news.html`) показывается только вошедшим пользователям.

**Рейтинг изданий** (`ratings.html`, `assets/ratings.js`). Список изданий лежит в таблице `outlets`. Оценки 1–5 хранятся в `outlet_ratings`: одна оценка на пользователя и издание, каждый видит и меняет только свои строки. Итоги для всех, без имён проголосовавших, отдаёт функция `outlet_stats()`. Место в рейтинге считается с поправкой на число оценок: к оценкам издания добавляются 3 условных голоса со средней оценкой по всем изданиям. Если в `scripts/prefetch.mjs` появляется новое издание, его нужно добавить и в `outlets`.

## Безопасность и производительность

- Все скрипты сайта лежат в `assets/`; на страницах стоит политика безопасности (CSP): браузер запускает только скрипты самого сайта.
- Библиотека входа (supabase-js) и карта суши для глобуса хранятся закреплёнными копиями в `assets/vendor/` (версии в `VERSIONS.txt`). Обновить их: задание «Обновить сторонние файлы» в Actions.
- В базе стоят ограничения на размер и формат данных и не больше 500 сохранённых новостей на человека.
- Новости хранятся в ветке `data`, которая перезаписывается целиком при каждом сборе (без истории), поэтому старые новости не копятся. Сайт публикуется заданием «Сайт и новости» через GitHub Actions: код из `main` плюс данные из `data`.
- Лента грузит облегчённые файлы `data/XX.json`; полные копии для сборщика лежат в `data/full/` (на сайт не публикуются). Файлы версионируются по `data/status.json`, поэтому повторные заходы берут их из кэша браузера.

## Администраторы

Администраторы могут удалять любые комментарии. Список хранится в закрытой таблице `private.admins`, изменить его можно только SQL-запросом в панели Supabase:

```sql
-- назначить
insert into private.admins (user_id) select id from auth.users where email = 'почта@пример.ru';
-- снять
delete from private.admins where user_id = (select id from auth.users where email = 'почта@пример.ru');
```

## Краткое изложение событий («Кратко»)

- **По расписанию.** При каждой сборке `scripts/prefetch.mjs` просит ИИ написать 2–3 предложения для 25 лучших событий каждой страны (сначала самые верхние в ленте). Результат: `data/summary.json`. Нужен секрет репозитория `LLM_API_KEY` и переменная `LLM_BASE_URL` (для Gemini: `https://generativelanguage.googleapis.com/v1beta/openai`). Модель выбирается автоматически по списку сервиса.
- **Пул нейросетей.** Можно подключить несколько сервисов сразу (`scripts/ai-pool.mjs`): каждый ключ добавляется секретом `LLM_KEY_<ИМЯ>` (`LLM_KEY_GROQ`, `LLM_KEY_MISTRAL`, `LLM_KEY_CEREBRAS`, `LLM_KEY_DEEPSEEK`, `LLM_KEY_OPENROUTER`, `LLM_KEY_TOGETHER`, `LLM_KEY_SAMBANOVA`, `LLM_KEY_NVIDIA`, `LLM_KEY_OPENAI`; любой другой сервис — секрет `LLM_KEY_EXTRA1` и переменная `LLM_BASE_EXTRA1` с адресом OpenAI-совместимого API). Необязательно: `LLM_MODEL_<ИМЯ>`, `LLM_BATCH_<ИМЯ>` (событий за запрос), `LLM_GAP_<ИМЯ>` (минут между запросами). Работает как цепочка: каждый свободный сервис берёт свою пачку событий, у кого кончился лимит (429) или случилась ошибка, тот отдыхает (время берётся из ответа сервиса), а пачку подхватывает следующий. Состояние каждого сервиса хранится в `data/summary.json` (поле `pool`), ключи туда не попадают.
- **По запросу читателя.** Если у события нет изложения, на странице события есть кнопка «Пересказать с помощью ИИ». Она вызывает Edge Function `summarize` в Supabase. Функция проверяет вход, лимиты (20 запросов в сутки на человека, 400 всего), берёт заголовки только из опубликованных данных сайта и сохраняет текст в `event_summaries` для всех. Ключ ИИ хранится в секретах Supabase (Edge Functions → Secrets): `LLM_API_KEY`, при необходимости `LLM_BASE_URL` и `LLM_MODEL`. В браузер и в репозиторий он не попадает.
