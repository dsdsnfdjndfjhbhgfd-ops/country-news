# ev.news

Сайт: https://dsdsnfdjndfjhbhgfd-ops.github.io/country-news/ (главная о проекте), лента: `news.html#RU`, страница события: `article.html?c=RU&u=<ссылка на статью>`

Вводишь страну и видишь главные события недели: только то, о чём пишут несколько изданий, без спорта и шоу-бизнеса.

- Новости берутся из открытой базы мировых СМИ [GDELT](https://www.gdeltproject.org/), русские и английские источники за 7 дней.
- 30 популярных стран собираются заранее GitHub Actions каждые 15 минут (три параллельных потока по 10 стран) (`scripts/prefetch.mjs` → `data/*.json`) и открываются сразу.
- Остальные страны запрашиваются у GDELT прямо из браузера (15–30 секунд), результат кэшируется в браузере на 30 минут.
- Ссылка на страну: `#KZ`, `#DE` и т. п.

## Аккаунты

Вход и регистрация через Supabase Auth (проект `ev-news`). Таблицы: `profiles` (мои страны, настройки ленты) и `saved` (сохранённые новости), доступ только к своим строкам (RLS). Код: `assets/account.js`, страница кабинета `account.html`. Лента (`news.html`) показывается только вошедшим пользователям.

## Безопасность и производительность

- Все скрипты сайта лежат в `assets/`; на страницах стоит политика безопасности (CSP): браузер запускает только скрипты самого сайта.
- Библиотека входа (supabase-js) и карта суши для глобуса хранятся закреплёнными копиями в `assets/vendor/` (версии в `VERSIONS.txt`). Обновить их: задание «Обновить сторонние файлы» в Actions.
- В базе стоят ограничения на размер и формат данных и не больше 500 сохранённых новостей на человека.
- Новости хранятся в ветке `data`, которая перезаписывается целиком при каждом сборе (без истории), поэтому старые новости не копятся. Сайт публикуется заданием «Сайт и новости» через GitHub Actions: код из `main` плюс данные из `data`.
- Лента грузит облегчённые файлы `data/XX.json`; полные копии для сборщика лежат в `data/full/` (на сайт не публикуются). Файлы версионируются по `data/status.json`, поэтому повторные заходы берут их из кэша браузера.

## Администраторы

Администраторы могут удалять любые комментарии. Список хранится в закрытой таблице `private.admins`, изменить его можно только SQL-запросом в панели Supabase:

```sql
-- назначить
insert into private.admins (user_id) select id from auth.users where email = 'почта@пример.ru';
-- снять
delete from private.admins where user_id = (select id from auth.users where email = 'почта@пример.ru');
```
